The important thing is that the project gradually stopped being “a better codec” and became a new framework for representing information.

The core idea in one sentence

ADG (Agnostic Data Generation) treats any file as a sequence of numbers, then replaces explicit storage with a deterministic engine that regenerates those numbers from a small set of initial conditions.

Not compression in the usual sense—causal generation.

The three engine classes

We kept circling around three distinct modes.

Lossless engine

Every value is exactly recoverable. More compute, stronger mathematical constraints.

Closed-form engine

Directly solve for frame 300 without iterating from frame 1. Random access becomes evaluation instead of replay.

Fractal / topological engine

The engine defines a geometry. Values travel through that geometry, allowing emergent structure and potentially pattern discovery.

The important distinction is that lossless becomes a property of the engine, not of the codec.

Anchors changed everything

Originally we talked about batches of 10 or 1000 frames.

The better idea was:

Treat the entire video as one continuous trajectory, with sparse anchor states.

So a two-hour film isn’t 216,000 independent frames—it’s one long evolution with occasional synchronization points.

That also enables seeking: jump to the nearest anchor and regenerate locally.

The bigger philosophical claim

This is where we need to stay disciplined.

We discussed the provocative idea that ADG might “rethink entropy.” That is not established.

What is established as a research direction is a much narrower statement:

Can deterministic generative processes become a practical alternative representation for arbitrary numerical sequences?

That’s a legitimate question.

A much stronger claim—such as universally exceeding Shannon limits or compressing arbitrary random data to 20,000:1—is not something we have evidence for. Shannon’s information theory is a mathematical theorem, so any ADG prototype would need to demonstrate where it fits within those limits rather than assume it overturns them.

Why the prototype comes first

You made a decision I think is exactly right:

No paper until there’s a working product.

The prototype doesn’t need to beat AV1. It only needs to answer one question convincingly:

Can one deterministic engine regenerate a nontrivial numeric sequence from a dramatically smaller representation?

If yes, then you have something worth formalizing. If not, the prototype will tell you why, and that’s often where the real invention happens.

At the moment, ADG is best thought of as a research framework with one concrete reversible mapping (RGB→scalar) and one unproven central hypothesis: that sufficiently expressive deterministic engines can replace explicit storage for broad classes of data. That’s the frontier we reached.

Not uber hard if we don't try to build the whole thing from scratch. In fact, this is one of the places where open source gives us a huge head start.

There are two different things, though:

A symbolic expression engine — quite manageable.

A system that discovers useful symbolic representations from arbitrary data and then algebraically compresses them — much harder, but we can build it incrementally.

For the first version, I'd use existing open-source machinery.

PySR on GitHub is probably the most interesting starting point. It's specifically designed to search for symbolic expressions and optimize them, with configurable operators and complexity. 

There's also gplearn on GitHub, which is pure Python and uses genetic programming to evolve expression trees.

The really nice thing
Existing symbolic-regression systems already deal with the ugly part of searching enormous expression spaces. PySR, for example, uses evolutionary search and explicitly supports controlling operators, constraints, and complexity. 

So we don't need to spend six months building:

"What if I randomly combine sin, sqrt, +, *, etc.?"

We can borrow the search engine and concentrate on the novel question:

What happens when symbolic discovery is embedded inside a reversible latent-space engine and judged by representation cost + exact residual?

That's a much better use of our effort.

And eventually we could replace the off-the-shelf symbolic search with our own specialized engine if the experiments show that ordinary symbolic regression is looking in the wrong space.

So no, I wouldn't consider the symbolic component a blocker at all. The first prototype could be quite achievable in Python. The hard part isn't making equations; it's figuring out what object the equations should be trying to represent and how to make their algebraic composition genuinely useful for the layered representation system.
